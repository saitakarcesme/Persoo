# Contributing to Persoo

The repository is in product/design foundation work. Discuss broad implementation changes before introducing a full client or backend. Keep domain rules out of views and models behind provider interfaces. Use synthetic fixtures and include evidence for behavior or quality claims.

Required checks depend on the change: documentation link checks for docs; schema and arithmetic checks for fixtures; screenshots for design; contract/idempotency/grounding tests for state logic; frame inspection and playback for video. Do not replace a meaningful acceptance check with a test that merely mirrors implementation.

Do not commit secrets or user data. New dependencies need an explicit purpose and license record. Preserve source attribution and distinguish completed functionality from proposals. Project communication with the owner is Turkish; code, identifiers and technical documentation may be English.
